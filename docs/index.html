核心觀念：兩層，兩種時間尺度

每一 frame 問 GPT 是死路：60 fps 等於每小時 216,000 次呼叫，延遲也不可能低於一個 beat。正確拆法是把「反應」和「意識」分開：

  • 反射層（TouchDesigner，每 frame）：Audio Device In → 頻譜 → bass / mid / high / energy / kick，直接調變幾何、shader、feedback。這層自己就能跑完一整場，GPT 掛了也不會黑畫面。
  • 導演層（Python sidecar + GPT-6，每 15–20 秒）：看的是 30 秒與 120 秒的趨勢、段落（build / drop / breakdown）、過去兩分鐘的視覺歷史，輸出一包參數 JSON：場景、色盤、對稱數、feedback 量、相機速度、粒子模式，以及「下一個 drop 來時要做什麼」。

兩層之間只靠 OSC 傳 JSON。導演改的是「目標值」，TD 用 Lag CHOP 花 2–4 個 beat 滑過去，所以 13 秒的決策延遲在畫面上感覺不到，只會覺得畫面「有在想事情」。

導演層為什麼走 Codex OAuth

你的機器上已經有完整條件：Codex 桌面版帶的 codex-cli 0.153.4（路徑 ~/.codex/plugins/.plugin-appserver/codex）、~/.codex/auth.json 是 chatgpt 登入模式、config.toml 預設 model 就是 gpt-6-astra。codex exec 支援 --output-schema，等於免費拿到 structured output，用量算在 ChatGPT 訂閱的 Codex 額度，不會產生 API 帳單。

三條路，選一條

現在就用
A · 每次決策開一個 codex exec

零 token 處理、完全走官方登入、已實測可行。代價是每次約 13 秒冷啟動，所以決策週期訂在 15–20 秒，drop 反應交給反射層。

第二階段
B · 常駐 codex app-server / mcp-server

同一個 codex 程序常駐，走 JSON-RPC 或 MCP 送 prompt，省掉冷啟動，理論上可壓到數秒。目前標 experimental，協定會變，等 A 版跑穩再上。

不建議
C · 直接拿 auth.json 的 access_token 打 chatgpt.com 後端

社群 proxy 的做法。快，但非官方端點、隨時會被擋，也偏離 ChatGPT 登入的使用範圍。演出中斷的風險不值得。

額度是未知數。每次 25k tokens，一小時 180 次就是 4.5M tokens，會撞到 Codex 的 5 小時與每週用量窗。正式演出前先做一次 60 分鐘 dry run，看桌面版的額度指示，決定週期要拉到 20 秒還是 30 秒。Fallback 導演一定要在，額度用完畫面照樣走。

執行方案

六個階段，每一階段都有可以獨立驗收的產出。第二階段完成時就已經是一台能上場的音樂視覺機，之後每一階段都只是加一層。

0半天

環境準備

  • BlackHole 2ch：brew install blackhole-2ch，裝完要登出或重開
  • TouchDesigner 2023 以上（Non-Commercial 版輸出上限 1280×1280，投影前確認夠用）
  • Python 3.11 以上建 venv（系統的 3.9.6 太舊）：python-osc numpy sounddevice，選配 aubio
  • Codex：已登入，確認 codex exec 可執行；把二進位路徑寫進 director 的設定
  • 選配：brew install projectm，或下載 projectM SDL 前端
驗收codex exec -m gpt-6-astra --output-schema schema.json -o out.json "..." < /dev/null 回傳合規 JSON
11 小時

音訊路由

  • Audio MIDI Setup → 左下「+」→ 建立多重輸出裝置，勾選你的喇叭或介面，再勾 BlackHole 2ch
  • 主裝置設成喇叭，BlackHole 那列勾 Drift Correction；把多重輸出裝置設為系統輸出
  • Apple Music 播放，TD 開 Audio Device In CHOP，Device 選 BlackHole 2ch，取樣率跟系統一致（48 kHz）
驗收喇叭有聲、CHOP 波形在動、Trail CHOP 看得到 kick 的尖峰
21–2 天

反射層：TD 自己就能演

  • 分析鏈：Audio Spectrum → 三段 Select → Analyze → Lag → Math 正規化；bass 走 Slope + Logic 做 kick 脈衝
  • 建一個 /director Base COMP，把 schema 裡每個欄位做成 Custom Parameter，全部視覺網路只引用這裡
  • 至少三個場景（tunnel、fractal_temple、particle_field）掛在 Switch TOP 上；每個場景都要吃 bass/mid/high
  • Feedback TOP、Kaleido、Lookup 色盤做成共用後製鏈
  • OSC In DAT 監聽 9001，callback 只做一件事：把值寫進 Custom Parameter
驗收不開 Director，手動拖 Custom Parameter，畫面 60 fps 反應且參數會滑，不會跳
3半天

特徵匯流

  • OSC Out CHOP 把六個特徵以 10 Hz 送到 9000（Sample Rate 設 10 即可，不要用 60）
  • sidecar 先只做接收與記錄：1 秒、30 秒、120 秒的滑動平均與斜率，段落判定（energy 低於 0.35 超過 4 秒 = breakdown；連續上升 20 秒 = build；breakdown 後 bass 突然回到 0.7 以上 = drop）
  • 把段落判定結果也送回 TD 一份 /feat/section，反射層自己也能用
驗收播一首完整的曲子，log 裡的 build / drop / breakdown 時間戳跟你耳朵聽到的一致
41 天

導演層：先規則，再 GPT

  • 先寫規則式導演：section 狀態機直接輸出同一份 JSON。這份之後就是 fallback，不會白做
  • 再加 GPT 路徑：每 15–20 秒（或段落切換當下）組 prompt，codex exec 拿 JSON，驗證後夾限，寫入視覺歷史，送 OSC
  • prompt 只放「現在」與「趨勢」的摘要，不放原始序列；視覺歷史給最近 8 筆，附時長
  • 鍵盤熱鍵切換 GPT / 規則 / 手動三種模式，演出時你永遠有否決權
驗收連跑 60 分鐘不中斷；拔掉網路，30 秒內 fallback 接手且畫面不閃
5半天–1 天

projectM 側鏈

  • projectM 獨立跑，音訊輸入選 BlackHole 2ch，preset 讓它自己輪播
  • 畫面進 TD：Syphon 走 Syphoner 抓 projectM 視窗 → Syphon Spout In TOP，延遲約 1 frame；或 OBS 視窗擷取 + NDI 外掛 → NDI In TOP，延遲 2–4 frames 但最穩
  • 導演只控 projectm_mix 與 Composite 的 blend mode，不去控 projectM 的 preset；要換 preset 就靠它自己的 hotkey 輪播
  • libprojectM 塞進 Custom TOP 這條先不碰：macOS 版 TD 已走 Metal，libprojectM 要 OpenGL context，工程量與 A 版整套差不多
驗收projectm_mix 從 0 滑到 1 的過程中 fps 不掉，MilkDrop 圖層與 TD 場景在同一個色盤下不打架
6持續

演出強化

  • 反重複：Director 拿到的歷史裡標出「上次用同組合的時間」，prompt 規則寫死 60 秒內不重複
  • Drop 預判：on_drop 一定要填，TD 端 drop 偵測器命中就執行，不等下一輪決策
  • 錄影：Movie File Out TOP 同步存檔，sidecar 的 log 帶時間戳，事後對照哪些決策好
  • MIDI 覆寫：一台小控制器接 TD，任何參數你手動一動就凍結該欄位 30 秒
  • 第二階段再評估 codex app-server 常駐，把 13 秒壓下去

程式碼骨架

director.py（sidecar 主迴圈）

import json, subprocess, time, collections, os
from pythonosc import udp_client, dispatcher, osc_server
import threading

CODEX = os.path.expanduser("~/.codex/plugins/.plugin-appserver/codex")
SCHEMA = "director_schema.json"
td = udp_client.SimpleUDPClient("127.0.0.1", 9001)
feat = collections.defaultdict(lambda: collections.deque(maxlen=1200))  # 120 s @ 10 Hz
history = collections.deque(maxlen=8)

def on_feat(addr, *args):
    feat[addr.split("/")[-1]].append((time.time(), args[0]))

def summarize():
    def avg(k, sec):
        now = time.time(); xs = [v for t, v in feat[k] if now - t <= sec]
        return round(sum(xs) / len(xs), 2) if xs else 0.0
    e30, e120 = avg("energy", 30), avg("energy", 120)
    trend = "rising" if e30 > e120 + 0.05 else "falling" if e30 < e120 - 0.05 else "flat"
    return dict(bass=avg("bass", 1), mid=avg("mid", 1), high=avg("high", 1),
                energy=avg("energy", 1), energy_trend_30s=trend, section=current_section())

def ask_gpt(summary):
    prompt = (SYSTEM_PROMPT + "\nNow: " + json.dumps(summary)
              + "\nVisual history (newest first): " + json.dumps(list(history)))
    out = "director_out.json"
    r = subprocess.run(
        [CODEX, "exec", "-m", "gpt-6-astra", "-c", 'model_reasoning_effort="low"',
         "-s", "read-only", "--skip-git-repo-check", "-C", "/tmp/director-cwd",
         "--output-schema", SCHEMA, "-o", out, prompt],
        stdin=subprocess.DEVNULL, capture_output=True, timeout=30)   # 沒有 DEVNULL 會掛死
    if r.returncode != 0: raise RuntimeError(r.stderr[-400:])
    return clamp(json.load(open(out)))

def rule_director(summary):
    ...  # section 狀態機，輸出同一份 JSON 結構

def publish(d):
    for k in ("scene","palette","feedback","symmetry","camera_speed","particle_mode","projectm_mix"):
        td.send_message(f"/director/{k}", d[k])
    td.send_message("/director/on_drop", json.dumps(d["on_drop"]))
    td.send_message("/director/heartbeat", int(time.time()))
    history.appendleft({"scene": d["scene"], "palette": d["palette"], "t": int(time.time())})

def loop(period=18):
    while True:
        s = summarize()
        try:    d = ask_gpt(s); src = "gpt"
        except Exception as e:
            d = rule_director(s); src = f"rule ({e.__class__.__name__})"
        publish(d); print(time.strftime("%H:%M:%S"), src, d.get("intent", ""))
        time.sleep(max(0, period - 13))   # 扣掉 exec 本身的耗時

TD 端：OSC In DAT 的 callback

def onReceiveOSC(dat, rowIndex, message, bytes, timeStamp, address, args, peer):
    d = op('/project1/director')            # 放 Custom Parameter 的 Base COMP
    key = address.split('/')[-1]
    if key == 'on_drop':
        op('on_drop_dat').text = args[0]    # kick 偵測器命中 drop 時再讀
    elif key == 'heartbeat':
        d.store('last_heartbeat', absTime.seconds)
    elif hasattr(d.par, key.capitalize()):
        getattr(d.par, key.capitalize()).val = args[0]   # Lag CHOP 在下游負責滑
    return

導演的系統提示（放在 director.py 的 SYSTEM_PROMPT）

你是一場 Psytrance 現場的視覺導演，管理整場演出的構圖節奏。只輸出符合 schema 的 JSON。
規則：
- 同一組 scene+palette 60 秒內不重複；連續三次決策至少換一次 scene。
- section=build 時逐步加 feedback 與 symmetry、壓低 camera_speed，把峰值留給 drop。
- section=breakdown 時降低複雜度：particle_mode=none 或 rain，projectm_mix ≤ 0.2。
- 每次都要填 on_drop，且不能跟上一次的 on_drop 相同策略。
- transition：段落內用 glide 8–16 beats；段落切換用 on_next_kick。
- intent 用 120 字內說明這次決策為什麼，會被記錄。
